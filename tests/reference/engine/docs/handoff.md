# Передача модуля команде HackAlem AI

Область разработчика № 1: данные, формула, валидатор, тесты и контракт. Frontend принадлежит разработчику № 2, API и AI-интеграция, общая сборка и финальная загрузка — разработчику № 3. Этот документ содержит заготовки сообщений; автоматически они никому не отправлялись.

## План в пределах 5 часов

| Время от старта | Работа разработчика № 1 | Результат для команды |
| --- | --- | --- |
| 0:00–0:30 | Перенести и сверить датасет, правила и контрольные значения | Единый каталог и формат входа |
| 0:30–1:30 | Реализовать формулу, лаги, синергии, ограничения показателей и валидатор | `simulateScenario()` и `getBaseline()` |
| 1:30–2:30 | Проверить контрольный пример, ошибки и граничные случаи | Автоматические тесты и CLI |
| 2:30–3:30 | Передать контракт, подключиться к интеграции frontend/backend | Реальные решения проходят один движок |
| 3:30–4:30 | Проверить основной пользовательский сценарий вместе с командой | 5 решений → бюджет → районы до/после → анализ |
| 4:30–5:00 | Исправить блокирующие ошибки, финально прогнать тесты и сверить README | Воспроизводимый командный релиз |

Коллеги могут работать параллельно после согласования контракта. Приоритет — рабочий основной сценарий; случайные события и автопрезентация не входят в обязательную часть модуля.

## Готовое сообщение frontend-разработчику

> Подготовлен `engine/index.mjs`: чистый синхронный ESM без зависимостей, работает в браузере и Node.js. Импортируй `RULES`, `CATEGORIES`, `INDICATORS`, `DISTRICTS`, `MEASURES`, `getBaseline`, `validateDecisions`, `simulateScenario`. Передавай массив `{measureId, districtId}`; у городских M2/M6/M12/M14 полностью опускай `districtId`. Ровно 5 разных мер, максимум 2 одного направления, бюджет 100. Не нужно покрывать все пять направлений. Цена и эффекты берутся из каталога. При `valid: false` показывай `validation.errors`, `result` равен `null`. Для исходного экрана используй `getBaseline()`, не пустой сценарий. У успешного ответа бюджет — `validation.budget`, итог — `result.after.score`, таблица — `result.districtChanges`. Округляй только при отображении. Контроль: 52.55768 → 56.54307, стоимость 95, остаток 5. На Node.js 24.19.0 прошли 74/74 теста. Подробности: `engine/docs/contract.md`; готовый пример ответа: `engine/examples/result.json`.

## Готовое сообщение AI/Integration-разработчику

> Расчётный модуль готов к подключению: `simulateScenario(decisions)` из `engine/index.mjs`. На backend повторно валидируй фактический пользовательский массив этим методом; не принимай клиентские значения цены, бюджета или Score за истину. Невалидный ответ содержит `result: null` и ошибки, его не нужно отправлять на анализ. В AI передавай только рассчитанный успешный результат с `validation.budget`, `baseline`, `after`, `delta`, `districtChanges`, `measureEffects`, `synergies`, `warnings`. AI объясняет готовые числа, сильные стороны и компромиссы; новые альтернативы сначала рассчитываются кодом. `measureEffects` — эффекты после лагов до ограничения показателей, не слагаемые Score; синергии идут отдельно. API-сервер, вызов OpenAI и fallback здесь не реализованы и остаются твоей частью. Запуск: `node --test engine/test/*.test.mjs`, `node engine/cli.mjs --demo`. На Node.js 24.19.0 прошли 74/74 теста. Контракт: `engine/docs/contract.md`; готовый пример ответа: `engine/examples/result.json`.

## Приёмка основного сценария

1. На одинаковом наборе решений порядок ввода не меняет результат; все команды получают один каталог и бюджет 100.
2. Baseline равен 52.55768; пример из `engine/examples/decisions.json` даёт 56.54307 при стоимости 95.
3. Отправка 4 или 6 решений, повтор меры, более 2 мер направления, превышение бюджета, неверные ID и несовместимости отклоняются.
4. Городские меры применяются ко всем районам один раз по стоимости, районные — к выбранному району; лаги и синергии отражены в результате.
5. Значение 40 не штрафуется; сумма эффектов ограничивается один раз; показаны районы и показатели до/после.
6. Изменение допустимого набора решений может менять Score; AI объясняет готовый результат без самостоятельного расчёта чисел.
7. Команды запуска из README воспроизводимы; backend проверяет реальные запросы; общий интерфейс показывает ошибки, бюджет и результаты.
