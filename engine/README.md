# Расчётный движок «Аким на 5 часов»

Модуль разработчика № 1 для HackAlem AI: синтетические данные, детерминированная формула Astana Quality of Life Score, проверка решений и тесты. Числа рассчитывает код; AI получает готовый результат и объясняет его. Frontend, HTTP-сервер и интеграция OpenAI в этот модуль не входят.

## Запуск

Нужен Node.js 20 или новее. Зависимостей нет, установка npm-пакетов не требуется. Из корня репозитория:

```sh
node --test engine/test/*.test.mjs
node engine/cli.mjs --baseline
node engine/cli.mjs --demo
node engine/cli.mjs engine/examples/decisions.json
```

CLI выводит JSON. Можно передать JSON-массив через stdin: `node engine/cli.mjs -`. Код завершения: `0` — успешный расчёт или baseline, `1` — невалидный сценарий, `2` — ошибка аргументов, чтения или JSON.

Проверено на Node.js 24.19.0: **74/74 теста прошли** (7 проверок данных, 63 проверки движка и валидатора, 4 проверки CLI). Проверка деклараций TypeScript 5.9.3 с `strict` и `exactOptionalPropertyTypes` также прошла; компилятор использовался для проверки, не является зависимостью продукта. Минимальная заявленная версия — Node.js 20; отдельный прогон на ней не выполнен. Интеграция с UI и проверка в браузере пока не выполнены.

Контрольные значения до округления: baseline **52.55768**; пример из `examples/decisions.json` — **56.54307**, стоимость **95**, остаток **5**. В интерфейсе: **52,56 → 56,54**. Пустой массив не является допустимым сценарием; исходное состояние получают через `getBaseline()`.

## Данные и правила

Источник — синтетический датасет, предоставленный пользователем для задания HackAlem AI. Это учебная модель, а не измеренные показатели Астаны. Единый источник данных — `data.mjs`: 5 районов, 10 показателей, 14 мероприятий, веса, лаги, синергии и несовместимости. Каталог заморожен от изменений во время выполнения.

- У каждой команды одинаковые исходные данные и бюджет **100** единиц.
- В итоговом сценарии ровно **5 разных мероприятий**, не более **2** одного направления. Повтор одного мероприятия в другом районе тоже запрещён.
- Все пять направлений доступны, но охватывать каждое из них одним сценарием не требуется.
- Районная мера действует в одном указанном районе. Городская применяется ко всем районам, оплачивается один раз; `districtId` для неё нужно полностью опустить.
- Клиент передаёт только идентификаторы. Стоимость, эффекты и бюджет берутся из каталога; присланные поля `cost`, `effects` или `budget` отклоняются.
- М1 и М3 несовместимы во всём городе; М4 и М7, а также М5 и М13 — только при выборе одного района.

## Формула

Горизонт `H = 8` кварталов. Реализованный эффект меры с лагом `L`:

```text
реализованный эффект = эффект из каталога × (8 − L) / 8
новый показатель = clip(исходный + сумма эффектов + синергии, 0, 100)
D[d] = сумма(вес показателя × показатель района d)
A = сумма(доля населения района d × D[d])
W = min(D[d])
N = число пар «район / показатель», где новый показатель строго < 40
Score = 0.7 × A + 0.3 × W − N
```

Сначала складываются все положительные и отрицательные эффекты и синергии, затем показатель ограничивается **один раз**. Значение ровно `40` не даёт штрафа. Готовый Score не ограничивается диапазоном 0–100 и теоретически может быть отрицательным: ограничены только показатели.

Синергии — фиксированные бонусы без дополнительного умножения на лаг:

| Пара мер | Район бонуса | Бонус |
| --- | --- | --- |
| M1 + M2 | район M1 | T1 +2 |
| M10 + M12 | район M10 | B1 +2 |
| M5 + M6 | район M5 | E2 +2 |

Промежуточные значения не округляются для отображения. Движок использует целочисленное масштабирование для точной арифметики текущего датасета с шагом показателя 1/8. Форматирование до двух знаков выполняется только в UI. При изменении горизонта, дробности эффектов или весов необходимо пересмотреть масштабирование и тесты.

## Подключение

```js
import {
  DISTRICTS, MEASURES, EXAMPLE_DECISIONS,
  getBaseline, validateDecisions, simulateScenario,
} from './engine/index.mjs';

const baseline = getBaseline();
const response = simulateScenario(EXAMPLE_DECISIONS);
if (!response.valid) {
  console.error(response.validation.errors);
} else {
  console.log(response.validation.budget, response.result.after.score);
}
```

Тот же ESM-файл работает в браузере: импортируйте `/engine/index.mjs` из `<script type="module">` при раздаче корня репозитория через HTTP либо подключите модуль через сборщик. Расчёт синхронный и не требует сети. Сервер, принимающий реальные пользовательские сценарии, должен повторно вызывать `simulateScenario()` на своей стороне: браузерная проверка не заменяет серверную.

`measureEffects` показывает эффекты мер после учёта лага, **до ограничения показателей**. Это не независимые слагаемые итогового Score: минимум по районам, штрафы и ограничение показателей делают результат нелинейным. Синергии перечислены отдельно. Для честного сравнения берите `districtChanges` и `delta`, а для оценки альтернативы пересчитывайте весь допустимый сценарий.

## Структура и передача команде

| Файл | Назначение |
| --- | --- |
| `data.mjs` | Данные, правила и контрольный сценарий |
| `index.mjs` | Валидатор и расчёт |
| `index.d.mts` | TypeScript-контракт экспортов |
| `cli.mjs` | Воспроизводимый запуск без UI |
| `examples/decisions.json` | Сценарий стоимостью 95 |
| `examples/result.json` | Сохранённый фактический вывод CLI для примера |
| `test/*.test.mjs` | Автоматические проверки |
| [docs/contract.md](docs/contract.md) | Полный контракт для frontend и backend |
| [docs/handoff.md](docs/handoff.md) | План на 5 часов и готовые сообщения коллегам |

Применимость движка — сравнение сценариев учебной модели. Неопределённость реальных городских эффектов в синтетические коэффициенты не включена.
