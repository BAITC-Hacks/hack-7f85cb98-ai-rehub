1. Общая концепция продукта
Пользователь получает единый бюджет 100, выбирает ровно пять разных мероприятий и видит, как они
меняют показатели пяти районов и итоговый Astana Quality of Life Score.
Главное отличие проекта - Counterfactual Policy Advisor. После расчёта система перебирает допустимые
замены одной выбранной меры, находит лучшие альтернативы и показывает: что заменить, какой Score
получится, какой район выиграет и какой компромисс возникнет.
Жёсткая граница ответственности
Формула, бюджет, лаги, синергии, конфликты и подбор альтернатив считаются кодом. LLM получает
готовые факты и только объясняет их. Это обязательное правило всей команды.
Обязательный путь пользователя
 Увидеть базовый Score 52,56 и исходные показатели районов.
 Выбрать ровно 5 мероприятий и районы для локальных мер.
 Получить понятную причину, если набор нарушает правила.
 Рассчитать Score, изменения районов и критические показатели.
 Нажать «Найти лучшую замену» и сравнить план с контрфактической альтернативой.
 Получить AI-объяснение сильных сторон, рисков и цены замены.

4. Правила валидации
 Ровно 5 решений; вариант «до пяти» запрещён.
 Общая стоимость не выше 100; остаток не даёт бонуса.
 Повторы мероприятий запрещены.
 Район обязателен только для scope = district; для городской меры район отсутствует.
 Не больше двух мер одного направления; следовательно, минимум три направления.
 M1 и M3 несовместимы при любом выборе районов.
 M4 и M7 несовместимы только в одном и том же районе.
 M5 и M13 несовместимы только в одном и том же районе.
 Для невалидного набора Score не рассчитывается, возвращаются все найденные причины.

districtScore = sum(indicator[k] * weight[k])
cityAverage = sum(districtScore[d] * populationShare[d])
criticalCount = count(indicator < 40)
finalScore = 0.7 * cityAverage
           + 0.3 * min(districtScore)
           - criticalCount

6. Контрфактический поиск
Функция findBestReplacement(current) должна заменить ровно одно решение. Для каждого из пяти слотов
перебираются все невыбранные меры и допустимые районы. Каждый кандидат проходит тот же валидатор и
тот же evaluateScenario. Возвращаются три лучших уникальных варианта.
type ReplacementCandidate = {
  removed: Decision;
  added: Decision;
  result: ScenarioResult;
  scoreGain: number;
  weakestDistrictGain: number;
  removedCriticalCount: number;
};
type AdvisorResult = {
  current: ScenarioResult;
  bestByScore?: ReplacementCandidate;
  bestForWeakestDistrict?: ReplacementCandidate;
  bestFastImpact?: ReplacementCandidate;
};
Критерий уникальности
Не отдавай просто глобально лучший набор. Советник должен показать понятную замену одного
решения: «убрать X, добавить Y, получить +Z». Это центральное демо проекта.
Стратегии

finalScore, затем меньше criticalAfter
Помощь слабому району
рост min(districtScore), затем finalScore
Быстрый эффект
минимальный лаг добавленной меры, затем finalScore
7. Тесты и Definition of Done
 Базовый Score совпадает с 52,55768 с погрешностью не более 0,0001.
 Пример из задания даёт бюджет 95 и Score около 56,54.
 Набор с M2/M3/M8/M9/M14 даёт бюджет 98 и Score около 57,24.
 Проверены превышение бюджета, повтор, отсутствие района, лишний район и три конфликта.
 Все индикаторы ограничены 0..100; значение ровно 40 не считается критическим.
 findBestReplacement не возвращает исходный набор и не нарушает правила.
 Функции не мутируют исходные массивы и дают одинаковый результат при повторном вызове.

9. Готовые промпты для Codex
Промпт 1 — расчётный движок
Работай только в src/data, src/domain, src/types и tests. Реализуй чистый TypeScript-движок симулятора «Аким на 5 часов» по
приложенному датасету. Перенеси все исходные значения и M1-M14 без изменений. Реализуй лаги, clip 0..100, веса, cityAverage,
criticalCount и итоговый Score. LLM не используется. Добавь тесты для базового Score 52.55768 и сценария из ТЗ около 56.54. Не
меняй UI, API route, README и package scripts без необходимости.
Промпт 2 — контрфактический советник
Добавь findBestReplacement(current). Замени ровно одно из пяти решений, перебери все невыбранные меры и районы,
отфильтруй невалидные варианты через существующий валидатор, рассчитай их тем же evaluateScenario. Верни лучшие
варианты по трём стратегиям: максимальный официальный Score, максимальный рост слабейшего района, быстрый эффект с
минимальным лагом. Не создавай новую формулу официального Score. Добавь детерминированные тесты.
Промпт 3 — ревью перед передачей
Проведи ревью только расчётной части. Проверь соответствие PDF: ровно 5 решений, бюджет 100, повторы, районные/городские
меры, максимум 2 меры направления, три несовместимости, три синергии, формулу и правило indicator < 40. Запусти тесты.
Исправь только подтверждённые ошибки и составь короткий handoff: экспортируемые функции, типы, тестовые примеры и
известные ограничения.
