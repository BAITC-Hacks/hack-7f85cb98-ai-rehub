# Аким на 5 часов

Симулятор решений для HackAlem AI: выберите пять мер для районов Астаны, сравните показатели и проверьте замену одного решения. Интерфейс, сервер и советник используют один расчётный движок. AI объясняет проверенные факты.

## Запуск

Требуется **Node.js ≥ 22.18** и npm. Проверено на Node 22.23.1. Lock-файл фиксирует зависимости: Next.js 16.3.6, React 19.2.8, TypeScript 5.9.3.

```bash
npm ci
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). Без ключа приложение рассчитывает сценарии и показывает локальный анализ. Для OpenAI скопируйте `.env.example` в `.env.local` (`Copy-Item .env.example .env.local` в PowerShell):

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6-sol
```

Перезапустите сервер после изменения окружения. Ключ используется только сервером; `.env.local` исключён из Git. Не добавляйте `NEXT_PUBLIC_` к имени ключа. Через `OPENAI_MODEL` можно выбрать доступную команде модель с Responses API и Structured Outputs.

## Демо за две минуты

1. **«Загрузить пример»**: M7/Нура, M8/Нура, M10/Нура, M12/весь город, M5/Сарыарка.
2. Бюджет **95/100**, исходный Score **52.55768**, результат **56.54307**, критических значений после мер **0**. Только отображение округляется до двух знаков.
3. Лучшая одиночная замена: **M5/Сарыарка → M3/Нура**, бюджет **100**, Score **57.20556**.
4. Примените замену: изменится один слот, старый результат скроется. Нажмите **«Рассчитать сценарий»**.
5. Поменяйте меру: старые расчёт и AI-анализ исчезнут; ошибки выбора блокируют расчёт.

Второй контрольный план: M2, M3/Нура, M8/Нура, M9/Нура, M14 — бюджет **98**, Score **57.236735**. Его лучшая допустимая одиночная замена снижает Score: интерфейс сообщает «Улучшение одной заменой не найдено». Это не доказательство глобального оптимума.

## Правила

- Ровно 5 разных мер, бюджет ≤ 100, не более 2 мер одной категории. Охват всех категорий не обязателен.
- У районных мер обязателен район; у городских `districtId` отсутствует. Есиль — `yesil`.
- M1/M3 несовместимы во всём городе; M4/M7 и M5/M13 — в одном районе.
- Показатель: `clip(I + Σ effect × (8 − lag)/8 + synergies, 0, 100)`. Сначала суммирование, затем clip.
- Оценка района — взвешенная сумма показателей. Итог: `0.7 × средняя по населению + 0.3 × минимум районов − число показателей < 40`.
- У невалидного плана итоговый Score равен `null`. Советник заменяет одну меру на новую, отсутствующую в исходном плане. Перенос той же меры между районами заменой не считается.

Полный контракт и вклад расчётной части: [документация движка](docs/engine/README.md).

## Архитектура и API

| Часть | Расположение |
| --- | --- |
| Данные / общие типы | `src/data/`, `src/types/simulation.ts` |
| Единый расчёт | `src/domain/index.ts`: `getBaseline`, `validateScenario`, `evaluateScenario`, `findBestReplacement` |
| Интерфейс | `src/app/page.tsx`, `src/components/`, `src/i18n.ts` |
| AI / fallback | `src/lib/ai/` |
| Серверный пересчёт | `POST /api/analyze` |

```json
{"decisions":[{"measureId":"M7","districtId":"nura"},{"measureId":"M8","districtId":"nura"},{"measureId":"M10","districtId":"nura"},{"measureId":"M12"},{"measureId":"M5","districtId":"saryarka"}]}
```

Опционально передайте `replacementDecisions` — второй полный набор с ровно одной новой мерой. Сервер пересчитывает оба плана; клиентские Score, бюджет и прирост не принимает. Нулевой и отрицательный прирост допустимы и описываются с правильным знаком.

Ответ: `{source, summary, strengths, risks, tradeoffs, recommendations}`. `source` — `openai` либо `fallback`. Неверный JSON, недопустимые решения и неправильная замена возвращают HTTP 400 до обращения к OpenAI. `useScenarioAnalysis` отменяет устаревшие запросы и различает ошибки выбора и недоступность анализа.

Сервер формирует факты из результатов движка. OpenAI через официальный SDK и Responses API возвращает идентификаторы фактов в порядке важности. Модель не создаёт новые числа. Отсутствие ключа, таймаут (20 секунд), ошибка API, неполный или неверный JSON включают fallback. Автоматических повторных платных запросов нет. Используется [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Проверки и production

```bash
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
npm run start
```

`check` останавливается при ошибке: строгие типы приложения/движка → ESLint → тесты AI/API → Node-тесты движка → регрессии → production-сборка Next.js → компиляция и smoke движка. Playwright запускает production-сервер на порту 4185 без ключа; проверяет desktop 1366×768 и mobile 390×844, реальный API, замену, ошибки, retry и отмену старого анализа.

Отдельно: `npm run test:app`, `npm run test:engine`, `npm run test:legacy`, `npm run typecheck`, `npm run lint`, `npm run build`. `tests/reference/engine/` используется только для регрессий; приложение её не импортирует. Обычные тесты не обращаются к платному API.

Контролируемый live-тест на отдельном изменённом районном датасете (PowerShell):

```powershell
$env:RUN_LIVE_AI='1'
node --env-file=.env.local node_modules/vitest/vitest.mjs run src/lib/ai/liveEvaluation.test.ts
Remove-Item Env:RUN_LIVE_AI
```

## Ограничения

Данные и эффекты синтетические; это модель хакатона, а не прогноз реального города. Обучение LLM не выполняется. Изменённые районные данные используются в тестах качества; загрузка произвольного датасета через UI/API не входит в этот объём работ. Русский AI-анализ использует OpenAI при наличии ключа; казахский и английский — локализованный детерминированный анализ. Поиск советника ограничен одной заменой.
